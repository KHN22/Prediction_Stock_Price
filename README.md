## โหลดและอ่านข้อมูล

- เปิดเว็บแล้วเลือก MU หรือ AMZN ได้ ระบบอ่านผลจาก `data/<หุ้น>.working.json` ก่อน หากไม่มีจึงใช้ `public/<หุ้น>.json` วันที่บนเว็บอ้างอิงชุดข้อมูลที่โหลด ไม่ใช่วันที่ปัจจุบัน
- ใช้ **อัปเดตข้อมูล → รวมกับประวัติเดิมและบันทึก** เพื่ออัปโหลดเฉพาะข้อมูลที่เพิ่มหรือแก้ไขโดยไม่ต้องมี API key กดดาวน์โหลดแม่แบบในหน้าต่างนี้ได้
- **ราคา** ใช้ชื่อ `mu_prices.csv` และคอลัมน์ `date,open,high,low,close,volume` เพิ่มทุกวันซื้อขายที่ขาดต่อจากชุดเดิมและใช้เกณฑ์การปรับราคาแบบเดียวกับประวัติ วันที่ซ้ำกับประวัติจะใช้ค่าที่นำเข้า
- **งบ** ใช้ `mu_quarterly_update.csv` ใส่วันสิ้นไตรมาส `fiscalDateEnding` และวันประกาศ `reportedDate` เป็น `YYYY-MM-DD` ไตรมาสใหม่ต้องมีรายได้ `totalRevenue` กระแสเงินสดจากการดำเนินงาน `operatingCashflow` (รายจ่ายลงทุน `capitalExpenditures` เป็นช่องเสริม) ใช้ตัวเลข USD เต็มโดยไม่ใส่ตัวคั่นหลัก ช่องเสริมเว้นว่างได้ ระบบใช้การเติมค่าขาดหายของโมเดลเดิมเมื่อไตรมาสใหม่มีข้อมูลไม่ครบ
- เมื่อต้องการแก้ไตรมาสเดิม ให้ใช้วันสิ้นไตรมาสและวันประกาศที่บันทึกอยู่ในชุดเดิม ใช้ตัวเลขที่เปิดเผย ณ วันประกาศนั้น หากเป็นการปรับย้อนหลังในรายงานรอบถัดไป การใส่ทับไตรมาสเดิมอาจทำให้ Backtest เห็นข้อมูลก่อนวันเผยแพร่จริง ส่วน Macro และไฟล์งบ raw เดิมอัปโหลดแยกได้ตามรายชื่อที่รองรับ
- ชุดราคา + Macro + งบการเงินแสดงงบกำไรขาดทุน งบฐานะการเงิน และงบกระแสเงินสด พร้อมประมาณการงวดถัดไปแยกตามรายการ วันที่พร้อมใช้ของงบและ Macro จะแสดงใต้กราฟ หากวันประกาศงบใหม่อยู่หลังวันราคาปิดล่าสุด โมเดลจะใช้ข้อมูลที่พร้อม ณ วันราคาปิด
- เมื่อรันโหมดรวมข้อมูลสำเร็จ ระบบบันทึกข้อมูลรวมและผลคาดการณ์ไว้ใน `data/mu.working.json` การเปิดเว็บหรืออัปเดตครั้งถัดไปจะใช้ชุดนี้ หากต้องการย้อนกลับ ให้ปิดเซิร์ฟเวอร์แล้วเปลี่ยนชื่อไฟล์นี้เก็บเป็นสำรอง
- โหมด **รันจากชุดไฟล์ใหม่** ยังรับ `mu_prices.csv` อย่างเดียวหรือครบ 6 ไฟล์ และแสดงผลเฉพาะเซสชันนั้น ไฟล์ราคาของโหมดนี้ต้องมีอย่างน้อย 1,100 วันซื้อขายหลังทำความสะอาด
- **Forecast** แสดงราคาปิดย้อนหลังและจุดคาดการณ์ที่ 21, 63 หรือ 126 วันซื้อขาย เส้นประเชื่อมจากราคาปิดล่าสุดไปยังจุดปลายช่วง
- **Backtest ของ MU** แสดงราคาจริง ราคาทำนาย และ Baseline มุมมองหลัก 3 เดือน / ราคา + Macro ล็อก Random Forest และเทียบ Momentum 21 วัน ส่วนช่องอื่นเลือก Baseline ที่ RMSE ต่ำที่สุดบนชุดทดสอบ การเลือกอ้างอิงย้อนหลังนี้ไม่ใช่การเลือกจากชุดพัฒนา และไม่เปลี่ยนค่าพยากรณ์
- ตัวเลขเป็นผลจากไฟล์ CSV ในโปรเจกต์หรือที่เลือกอัปโหลด วันที่ในหน้าเว็บจึงอ้างอิงข้อมูลชุดนั้น

## ติดตั้ง Python สำหรับรันโมเดล

บน Windows หากย้ายโปรเจกต์พร้อมโฟลเดอร์ `.runtime` ทั้งชุด ให้เปิด **Start Model 411.cmd** จากตำแหน่งใหม่ เซิร์ฟเวอร์จะปรับพาธของ Python ที่อยู่ในโปรเจกต์ให้โดยอัตโนมัติ หากเครื่องปลายทางไม่มี `.runtime` ให้สร้าง environment ด้วย Python 3.12

```powershell
py -3.12 -m venv .runtime/venv
& ./.runtime/venv/Scripts/python.exe -m pip install -r requirements.txt
npm start
```

หากใช้ Python ที่ติดตั้งไว้ในตำแหน่งอื่น ให้ตั้ง `MODEL_PYTHON` เป็นพาธของ executable ก่อนเปิดเซิร์ฟเวอร์

## โมเดล MU และ AMZN

**MU** ใช้ 3 ระยะ 21/63/126 วันซื้อขาย กับชุดตัวแปร A ราคา, B ราคา + Macro และ C ราคา + Macro + งบ รวม 9 ผลเมื่อข้อมูลครบ ฐานใน notebook ปัจจุบันคือค่าเฉลี่ยย้อนหลัง 63 วันของ log return 21 วัน (`baseline_momentum_log`) โมเดลเรียนรู้ส่วนต่างจากฐาน แล้วคำนวณ `predicted_log_return = base + blend_weight * residual` น้ำหนักอยู่ในช่วง 0–1 หากเป็น 0 ผลจะมาจากฐานทั้งหมด ฐานในสมการนี้ต่างจาก Momentum 21 วันล้วนที่ใช้เทียบใน Backtest

**AMZN V4** ใช้ `amzn_prices.csv`, `amzn_market.csv` (VIX) และ `amzn_earnings.csv` ครบ 3 ไฟล์ เปรียบเทียบ HAR, HAR + VIX, HAR + earnings, GJR-GARCH และ stacking เพื่อพยากรณ์ log volatility จากนั้นใช้ rolling conformal สร้างค่ากลาง p50 และช่วงราคา 80%/95% ทั้งสามระยะ ปุ่มออนไลน์ดึงราคาและ VIX ย้อนหลังตั้งแต่ปี 2015 พร้อมวันงบที่หาได้และประมาณการรายไตรมาส กราฟอ้างอิงใช้ช่วงราคาคงสเกล (constant-scale intervals)

คะแนน AMZN แยกหน้าที่กัน: RMSE บน CV วัด **log volatility** เทียบ naive volatility; ทิศทางวัดค่ากลางของช่วงราคาบน CV ที่เลือกจุดไม่ทับซ้อน; กราฟ Backtest และ coverage ใช้ Holdout ฟิลด์ RMSE ของผลใหม่ใช้ `model_RMSE_log_volatility` และ `best_baseline_RMSE_log_volatility` หน้าเว็บรองรับ snapshot เก่าที่บันทึกชื่อฟิลด์เป็น log return โดยตีความเป็น volatility สำหรับ AMZN และไม่แก้ไฟล์ข้อมูลเดิม คะแนนนี้เปรียบเทียบตรงกับ RMSE ผลตอบแทนของ MU ไม่ได้

**Notebook และงานทดลอง:** adapter ค้นหา code cell ตามข้อความระบุบทบาท แทนการยึดตำแหน่งเซลล์ หากหาไม่พบหรือพบซ้ำจะแจ้งข้อผิดพลาดก่อนประมวลผล หากเปลี่ยนโค้ดส่วนหลัก ต้องปรับตัวระบุใน adapter ให้ตรงด้วย โฟลเดอร์ `experiments/mu_horizons/` เป็นผลทดลองจาก snapshot ที่ตรึงไว้ รายงานภายในอธิบายสูตร Control ณ เวลาทดลอง จึงอาจต่างจาก notebook และผลใช้งานปัจจุบัน

## โมเดลและการเพิ่มหุ้น

`models/mu.py` ใช้เซลล์สร้างตัวแปรและประเมินผลจากโน้ตบุ๊กเดิม โดยใช้ chronological walk-forward, purge ข้อมูลตามวันที่เป้าหมาย และประเมินช่วงทดสอบที่กันไว้ หลังเลือกอัลกอริทึมในแต่ละคู่ช่วงเวลาและชุดตัวแปรแล้ว ระบบฝึกซ้ำด้วยแถวที่ทราบผลจริง ณ วันปิดล่าสุดเพื่อคาดการณ์ ผลที่แสดงใน Backtest มาจากโมเดลก่อนฝึกซ้ำ

วิธีเตรียม Macro และวันประกาศงบใช้สมมติฐานเดิมในโน้ตบุ๊ก ค่า RMSE ของการรันใหม่อาจต่างจากผลที่บันทึกในโน้ตบุ๊กเล็กน้อยตามเวอร์ชันไลบรารี และช่วงทดสอบรายวันของระยะ 3 และ 6 เดือนมีช่วงเป้าหมายซ้อนทับกัน

เพิ่ม adapter ใน `models/` และลงทะเบียนใน `models/run.py` จากนั้นเพิ่มสัญลักษณ์ ชื่อบริษัท สกุลเงิน และชื่อไฟล์ใน `server.mjs` ตัวเลือกหุ้นบนหน้าเว็บอ่านจาก registry ผ่าน API ให้ adapter ส่ง JSON ตามโครงสร้าง `public/mu.json` โดยแต่ละรายการใน `results` มี horizon, sessions, forecast, return, metrics และแถว `test` รูปแบบ `[targetDate, actualClose, predictedClose, baselineClose]` จากนั้นวางไฟล์ใน `data/` และรัน `npm run refresh` เพื่อสร้างผลเริ่มต้น

## อัปเดตจากอินเทอร์เน็ต

กด **อัปเดตออนไลน์และคำนวณใหม่** เพื่อดึง OHLCV รายวันจาก Yahoo Finance งบ MU จาก SEC EDGAR และ Macro จาก FRED จากนั้นระบบรันโมเดลเดิมและบันทึกผลในเครื่อง ต้องเชื่อมต่ออินเทอร์เน็ตและอาจใช้เวลาหลายนาที หากแหล่งข้อมูลล้มเหลว ระบบจะแสดงข้อผิดพลาดและเก็บผลที่บันทึกสำเร็จไว้

สำหรับ MU ระบบดึงประวัติราคา 5 ปีใหม่ทั้งหมดเพื่อให้การปรับปันผลและ split อยู่บนฐานเดียวกัน ใช้เฉพาะแท่งวันที่ปิดตลาดแล้ว โดยเผื่อหลังตลาดปิด 15 นาที งบใช้ 10-Q/10-K ตามวันที่สิ้นงวดจริง และถือว่าพร้อมใช้หลังวันยื่น SEC หนึ่งวัน ข้อมูลกระแสเงินสดสะสมและรายได้สะสมแปลงเป็นรายไตรมาสด้วยผลต่างของงวดที่มีจุดเริ่มต้นเดียวกัน

แหล่ง SEC มีตัวแปรบางรายการไม่ครบ เช่น EPS estimate และ surprise รวมถึง EPS รายไตรมาสที่ไม่มีข้อมูลตรง โมเดลใช้กระบวนการเติมค่าขาดหายเดิม Macro ดึงจากตารางข้อมูลสาธารณะ FRED โดยไม่ใช้ API key และแสดงงวดล่าสุดกับค่าที่โมเดลใช้ใต้กราฟ แหล่งข้อมูลฟรีอาจจำกัดการเรียกหรือเปลี่ยนรูปแบบได้

[Yahoo Finance MU](https://finance.yahoo.com/quote/MU/) · [SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)


Macro ทั้งห้าตัวจับคู่กับ CPIAUCSL, FEDFUNDS, UNRATE, GS10 และ GDPC1 ตามลำดับ ใช้ระดับ CPI และ Real GDP หน่วยเดิม และอัตราดอกเบี้ย/ว่างงานเป็นเปอร์เซ็นต์ GS10 เป็นค่าเฉลี่ยรายเดือนของผลตอบแทนพันธบัตร 10 ปี GDP เป็นรายไตรมาส จึงเลื่อนวันที่จากต้นไตรมาสไปต้นไตรมาสถัดไปก่อนให้กระบวนการเดิมเลื่อนอีกหนึ่งเดือน ใช้ forward fill ระหว่างงวดที่ประกาศ ไม่มีการ interpolate ด้วยข้อมูลไตรมาสถัดไป

การเลื่อนหนึ่งเดือนเป็น proxy ตามโน้ตบุ๊ก ไม่ใช่วันประกาศจริงรายตัว ประวัติที่ดึงเป็นข้อมูลฉบับล่าสุดซึ่งอาจแก้ไขย้อนหลัง จึงยังมีข้อจำกัดสำหรับ Backtest แบบ point-in-time ปุ่มออนไลน์จะบันทึกข้อมูลและผลใหม่หลังดึงครบและคำนวณสำเร็จเท่านั้น หาก FRED ชุดใดล้มเหลวจะแสดงชื่อชุดนั้นและเก็บผลก่อนหน้าไว้

แหล่ง Macro [FRED](https://fred.stlouisfed.org/) ใช้ตารางสาธารณะ /data/{series} เนื่องจากช่อง graph.csv ไม่พร้อมใช้งานในการทดสอบครั้งนี้

## AMZN: Backtest ที่ตรวจสอบได้และคำอธิบายคำพยากรณ์

เลือก AMZN แล้วเปิด Backtest เพื่อดูคะแนนที่คำนวณจากจุดบนกราฟเดียวกันทั้งโมเดลและวิธีอ้างอิง มี RMSE log return ของค่ากลาง, MAE ราคา, ทิศทาง และสำหรับ AMZN มี coverage 80%/95%, ความกว้างเฉลี่ยเทียบราคาวันออกพยากรณ์ และ interval score หน่วย log return แยกจาก RMSE log volatility บน CV ด้านบน เลือกทุกวันหรือเว้น origins ไม่ให้ช่วงเป้าหมายทับซ้อนกันได้ พร้อมจำนวนจุดและข้อจำกัดของตัวอย่างน้อย กราฟระบุจุดหลุดกรอบ 80% และตรวจวันออก/วันครบกำหนดกับราคาจริงทีละจุดได้

ผล AMZN ใหม่เก็บ `backtestOrigins` และ `baselineIntervals` ของ constant-scale conformal บนวันเดียวกัน ผลเก่าอนุมาน origin จากประวัติราคาและ horizon เมื่อทำได้ แต่ไม่สร้างกรอบ baseline ขึ้นเองหากไม่มีข้อมูล ต้องรันใหม่เพื่อเปรียบเทียบ interval score ครบทั้งสองวิธี Holdout AMZN เคยถูกดูระหว่างพัฒนาแล้ว จึงต้องติดตามคำพยากรณ์ล่วงหน้าเพิ่มเติมก่อนอ้างว่าเป็นหลักฐานจากอนาคตที่ไม่เคยเห็น

`explanation` วัดความไวของคำพยากรณ์ล่าสุดโดยแทนข้อมูลทีละกลุ่มด้วยค่ามัธยฐานจากข้อมูลฝึกที่ทราบ target แล้ว ตรึงโมเดลและกลุ่มอื่นไว้ AMZN รายงานผลต่อความผันผวนจากส่วน HAR ของโมเดลที่เลือก โดยตรึง GJR ใน stacking ไว้ จึงไม่ใช่อันดับครบทุกปัจจัยภายใน GJR ไม่ใช่เหตุและผลของราคาตลาด ค่ารายกลุ่มบวกกันไม่ได้และไม่ใช่สัดส่วนความสำคัญรวม 100% ผลเก่าที่ไม่มีคำอธิบายจะไม่แสดงอันดับสมมติ

ตรวจส่วนประเมินและคำอธิบายด้วย `node --test tests/*.test.mjs` และ `python -B -m unittest discover -s tests -p "test_*.py"` ต้องติดตั้ง dependencies ตาม requirements สำหรับการทดสอบ Python

ส่วน Backtest และคำอธิบายเพิ่มเติมในหัวข้อนี้ใช้เฉพาะ AMZN ส่วน MU ใช้หน้าและผลที่บันทึกไว้ก่อนเพิ่มฟีเจอร์ชุดนี้
