# MU · ผลตรวจ Forecasting Pipeline และการทดลอง Baseline แยกตามระยะ

**ข้อสรุปสำหรับ Model Gate** เก็บระบบปัจจุบันเป็น Control และให้ 6 เดือนอยู่ระหว่างทดสอบ จุดที่มีหลักฐานให้ติดตามต่อคือ Random Forest ชุดราคา + Macro ระยะ 3 เดือนเมื่อให้เรียนจากฐานราคาคงเดิม ส่วน −35.26% ของชุดรวมงบ 6 เดือนอธิบายได้ครบจาก Momentum 21 วันและกลไกลดน้ำหนัก ML

ใช้ข้อมูลจากปุ่มออนไลน์ที่บันทึกไว้ถึง **25 พฤศจิกายน 2026** ราคาปิดปรับปรุงแล้ว $601.25 มี 1,255 วันซื้อขายตั้งแต่ 26 พฤศจิกายน 2021 เก็บสำเนาอินพุตทั้งหกชุดพร้อมผล Control ไว้ในโฟลเดอร์ทดลอง การทดลองทั้งหมดทำงานออฟไลน์

## 1 · โมเดลเดิมคำนวณอะไร

สำหรับวันปิดตลาด t เป้าหมายคือ y = ln(P[t+h] / P[t]) โดย h = 21, 63, 126 วันซื้อขายตามลำดับ Target เป็นผลตอบแทนสะสมตลอดช่วง จึงเทียบกับผลตอบแทนในหน่วยเดียวกันได้ ฐานที่ใช้สร้างผลทำนายจริงทุกช่องคือ b = ln(P[t] / P[t−21]) ทั้งสามระยะได้ค่า b เท่ากันที่วันออกพยากรณ์เดียวกัน วันต้นประวัติที่ยังคำนวณ Momentum ไม่ได้ใช้ 0

ตัวเรียนรู้ฝึกทำนาย y−b แล้วนำค่าทำนาย Residual ของสมาชิกมาเฉลี่ยเป็น r ผลสุดท้ายคือ **ŷ = b + w × r** และราคาคาดการณ์คือ P[t] × exp(ŷ) สำหรับระยะ 3 เดือนชุด B ใช้ Random Forest ตามการตั้งค่าหน้าหลัก อีกแปดช่องเลือกสามสมาชิกจาก Ridge, Random Forest, Extra Trees และ Histogram Gradient Boosting ด้วยผล validation น้ำหนัก w มาจากผลทำนายนอกชุดฝึก และจำกัดให้อยู่ระหว่าง 0 กับ 1 น้ำหนักนี้กำกับทั้ง Residual ไม่ใช่น้ำหนักรายตัวแปร

**Baseline บน Dashboard มีสองบทบาท** ฐานในสมการคือ M21 เสมอ ส่วนชื่อวิธีอ้างอิงที่แสดงใน Backtest ของมุมมองหลักล็อกเป็น M21 ช่องอื่นเลือกวิธีที่ RMSE ต่ำสุดบน *test* ระหว่างราคาคงเดิม ค่าเฉลี่ยย้อนหลัง และ M21 การเลือกชื่ออ้างอิงย้อนหลังนี้ไม่เปลี่ยน forecast แต่ให้ความได้เปรียบกับ benchmark ในรายงาน การทดลองใหม่เลือกฐานจาก development เท่านั้น

## 2 · เหตุที่งบการเงินชุด C ระยะ 6 เดือนได้ w = 0

ทำซ้ำการฝึกของสมาชิกเดิมบน validation สามช่วง ได้ 11 จุดต่อช่วง รวม 33 จุด สมการก่อนจำกัดช่วงคือ Σ[(y−b)r] / Σ[r²] ตัวเศษแต่ละช่วงคือ **−4.049, +0.213, +0.314** รวม −3.522 ตัวส่วนรวม 39.331 จึงได้ **−0.08955 → 0** วันล่าสุดฐาน −35.26% บวก ML 0.00 จุดเปอร์เซ็นต์ ได้ราคา **$389.23** ฐานนี้นำผลตอบแทนย้อนหลัง 21 วันมาใช้หนึ่งครั้ง ไม่มีการทบต้นหกครั้ง

ทดสอบโดยตรึงสมาชิก HGB + Ridge + RF แล้วเปลี่ยนเฉพาะกลุ่มอินพุต น้ำหนักก่อนจำกัดช่วงของ A / B / C เท่ากับ **0.129 / 0.388 / −0.090** ระยะนี้ B และ C ใน Control มีสมาชิกสามตัวเดียวกันอยู่แล้ว ผลจึงชี้ถึงความเปลี่ยนแปลงของ Residual เมื่อเพิ่มงบโดยตรง

- ช่วงฝึกแรกมีงบที่ปรากฏเพียง **4 งวด** ในวัน validation 27 ก.ค. 2023 กำไรขั้นต้นเปลี่ยนจากบวกในชุดฝึกเป็นขาดทุน ค่า signed-log ของกำไรขั้นต้นออกไปถึง −896 ส่วนเบี่ยงเบนมาตรฐานของชุดฝึก Ridge ให้ Residual −5.866 หน่วย log ซึ่งไกลกว่าสมาชิกต้นไม้สองตัวที่มีค่าสัมบูรณ์สูงสุดในช่วงเดียวกันเพียง 0.262 และ 0.296
- เมื่อแยกสมการ Ridge ที่จุดนั้น ตัวแปร signed-log ของกำไรขั้นต้น กำไรดำเนินงาน และกำไรสุทธิมีส่วน −2.522, −1.850 และ −0.922 หน่วย log ตามลำดับ เป็นการอธิบาย **โมเดลที่จุดนี้** การเรียงขนาดดังกล่าวใช้สรุปเหตุทางเศรษฐกิจไม่ได้
- ทดลองเฉพาะ development โดยจำกัดค่าหลังมาตรฐานของ Ridge ที่ ±5 ทั้งตอนฝึกและทำนาย ขนาดสูงสุดของ Ridge ในช่วงแรกลดจาก 5.866 เป็น 0.396 และ RMSE ของ ensemble ก่อนลดน้ำหนักรวมสามช่วงลดจาก 1.2342 เป็น 0.4048 แต่ค่า w ก่อนจำกัดยังเป็น −0.0228 และฐานล้วนได้ RMSE 0.3436 การควบคุมค่าหลุดช่วงแก้พฤติกรรมการคำนวณได้ โดยยังไม่มีหลักฐานให้เพิ่มน้ำหนักงบ การทดสอบนี้เกิดหลังเห็นอาการและใช้เพื่อวินิจฉัยเท่านั้น

**กลุ่มทดลอง** (1) Control ตาม snapshot (2) สมาชิก ML เดิมพร้อมกฎลดน้ำหนักและจุด validation แบบเดิม แต่ฝึก Residual ใหม่บนฐานที่ชนะ development ของแต่ละระยะ (3) Ridge α=100 เหมือนกันทุกช่อง มีทั้งกิ่ง M21 และฐานที่เลือกใหม่ เพื่อแยกผลของชุดตัวแปรภายใต้ตัวเรียนรู้เดียว (4) ฐานที่ชนะล้วนสำหรับวัดมูลค่าที่ ML เพิ่ม สมาชิกเดิมใช้ validation แบบเว้นจุดเช่นเดียวกับ Control ส่วน Ridge ใช้ทุก origin ของ validation จึงควรเทียบภายในคู่ของตนก่อน

## 4 · สูตรฐานที่ได้ทดลอง

M21 และ horizon momentum ใช้ผลตอบแทน log ย้อนหลัง 21 วันและ h วันตามลำดับ **Decayed** เฉลี่ยผลตอบแทนของบล็อก 21 วันที่ไม่ซ้อนกันย้อนหลังจนครบ h โดยให้น้ำหนักบล็อกที่เก่าขึ้นเป็น 0.65 เท่าต่อบล็อก **Multi-period** เฉลี่ย M21, M63/3 และ M126/6 **Reversal** ใช้ −0.5 × Momentum ย้อนหลัง h วัน **Drift** ใช้ค่าเฉลี่ยเป้าหมาย h วันที่รู้คำตอบแล้วในชุดฝึกของรอบนั้น **Flat** ให้ log return = 0 สูตรแบบเฉลี่ยจงใจลดขนาดแรงผลักจากช่วงสั้น ช่วงต้นที่ไม่มีประวัติของบล็อกนั้นใช้ 0 ทุกชุดตัวแปรใช้ฐานเดียวกันภายใน horizon

**RMSE ของฐานล้วนบน development** ใช้ทุก origin ของ fold เลือกค่าต่ำสุดแยกต่อ horizon โดยไม่มีการใช้คะแนน final test

- **อิทธิพลรายกลุ่ม** ในกิ่ง Ridge/M21 ที่ใช้กติกาเดียวกัน การเพิ่ม Macro ที่ 6 เดือนทำให้ RMSE จาก 0.9801 เป็น 1.2283 การเพิ่มงบต่อทำให้เหลือ 0.9329 ด้วยการปิด Residual ทั้งหมด ที่ 3 เดือนเพิ่ม Macro จาก 0.5121 เป็น 0.5777 และเพิ่มงบกลับมา 0.5230 ความเปลี่ยนแปลงนี้รวมผลของการฝึกใหม่และ w เป็นการวัดประโยชน์ส่วนเพิ่มแบบ A→B→C ผลเชิงสาเหตุหรือสัดส่วนความสำคัญแบบคงที่ของตัวแปรแต่ละกลุ่มยังระบุไม่ได้

## 7 · วันทำนาย ความล่าช้า และข้อจำกัดทางสถิติ

- ตรวจทุกแถวที่มี target ว่าวันปลายทางเป็นวันซื้อขายลำดับ t+h ราคาจริงเท่ากับ P[t+h] และราคาทำนายมาจากราคาตั้งต้น P[t] × exp(ŷ) วันที่ในกราฟ Backtest เดิมเป็น **วันปลายทาง** เปรียบเทียบกับราคาจริงวันเดียวกัน ไม่พบการเลื่อนผิด h วัน ไฟล์ [predictions.csv](results/predictions.csv) เก็บทั้งวันออกและวันเป้าหมาย
- 6 เดือน C เดิมมี MAE ราคาประมาณ $423.06 ต่อหุ้น ใน 50 จุดที่ผลตอบแทนอนาคตกลับเครื่องหมายจาก M21 มี MAE 1.1506 หน่วย log เทียบกับ 0.8621 โดยรวม เมื่อเทียบการเปลี่ยนแปลงรายวันของผลตอบแทน h วันบนแกน target สหสัมพันธ์ที่ lag 0 คือ −0.305 และที่ให้ forecast ตาม actual 21 วันคือ +0.416 เป็นลักษณะเชิงพรรณนาของเส้นที่ประกอบจากราคาย้อนหลังและหน้าต่างซ้อนทับ ยังใช้ระบุว่าโมเดลช้า 21 วันจริงไม่ได้
- ตรวจ backward join ซ้ำครบ 18,825 ช่อง Macro และ 61,495 ช่องงบ ตรงกับตารางที่กำหนดวันพร้อมใช้ ตัวดึง SEC เลือกข้อมูลที่ filed ไม่เกินวันที่ยื่นที่ใช้ แล้วให้ใช้ตั้งแต่วันถัดไป ชุด earnings นี้มีวันที่รายงานครบ งบ 6 เดือนในชุดฝึกสุดท้ายมีเพียง **14 งวด** แต่มี 49 ตัวแปรงบ พบ **38 คู่** ที่ |Spearman| ≥ 0.98 ทั้งค่าดิบและค่า signed-log ปรากฏร่วมกันหลายรายการ การใช้ซ้ำรายวันไม่ได้เพิ่มจำนวนไตรมาส
- Macro ใช้ค่าจาก FRED ฉบับที่ดึงล่าสุด พร้อมเลื่อนวันที่รายเดือน และเลื่อน GDP จากต้นไตรมาสไปหลังสิ้นไตรมาสก่อนใช้ lag การเลื่อนวันดังกล่าวยังไม่รับรองวันเผยแพร่จริงของทุกรายการหรือค่าที่รู้ได้ ณ เวลานั้น ประวัติราคาปรับปรุงแล้วก็เป็น snapshot เดียวเช่นกัน ขอบเขตที่ตรวจยืนยันได้คือการแบ่งชุด การจัดวันที่ และการคำนวณภายใน snapshot หากต้องยืนยันแบบ point-in-time ครบถ้วน ควรใช้วันประกาศจริงและ ALFRED vintage [คำอธิบาย real-time periods ของ FRED](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)

## 8 · การตัดสินใจ

1. เก็บ Control ไว้เป็นเกณฑ์อ้างอิงและ **ยังไม่แทนที่ Dashboard** สำหรับ 6 เดือน ควรแสดงหรือรายงานแยกว่าฐานสร้างผลตอบแทนเท่าใด และ ML เพิ่มเท่าใด โดยเฉพาะรอบที่ w = 0
2. ล็อกสูตร **3 เดือน B / RF / ฐานราคาคงเดิม** เป็นตัวทดลองติดตามคู่กับระบบเดิม บันทึกผลล่วงหน้าพร้อมวันออกและวันครบกำหนด คะแนนรวมต้องอ่านคู่กับความสามารถจับช่วงขาลง
3. สำหรับงานงบ ให้เพิ่มจำนวนรอบผลประกอบการที่ครอบคลุมกำไรและขาดทุน ทดสอบตัดตัวแปรซ้ำ และคุมการ extrapolate ของ Ridge ภายใน fold การทดสอบขีดจำกัดครั้งนี้แสดงว่าต่อให้ลดค่าผิดปกติได้ ก็ยังต้องพิสูจน์ประโยชน์ของ Residual บนช่วงเวลาใหม่
